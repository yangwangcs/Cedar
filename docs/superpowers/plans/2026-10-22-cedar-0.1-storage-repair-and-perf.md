# Cedar 0.1 存储层修复与性能优化 Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL — subagent-driven-development or executing-plans. Steps use "- [ ]" checkboxes.

Goal: 在不改变现有设计基础（32B CedarKey、Zone-Columnar v1 五区格式、Size-Tiered 分层模型、单 WAL、公开 API）的前提下，修复 0.1 存储层的正确性缺陷，并对版本链跳表、列式存储、LSM 合并做可量化的针对性性能优化。

Architecture: 先建立可构建、可基准、可回归的基线，再按"持久化与删除 → 边语义与格式 → 跳表并发/分配 → 列式读取/索引 → 合并算法/调度"的顺序推进。每个任务以失败测试开始、以基准数据结束；所有改动都不触碰 key 编码和 SST 布局，跨版本兼容通过 header 保留位与读端 fallback 实现。

Tech Stack: C++17、CMake、GoogleTest、LZ4、protobuf/gRPC（已有依赖）、POSIX（mmap/pread）、TSan/ASan。

Spec: docs/audit/0.1-storage-audit-2026-10-22.md（审计报告；每个正确性任务引用其中编号）。

## Global Constraints

- Key 不变：CedarKey 保持 32 字节、字段偏移、Encode/Decode 语义与 ~timestamp 编码不变。
- SST 布局不变：Header 256B、Footer 128B、5 Zone、ZoneMap 32B、RestartPoint 16B 的尺寸与偏移语义不变；不提升 kZoneColumnarVersion。新旧写法用 ZoneColumnarHeader::flags 保留位区分，读端兼容旧文件。
- 设计模型不变：单 WAL、LockFreeVSL、自研列式 SST、Size-Tiered L0–L6 容量触发；不引入 RocksDB/LevelDB、不改 B+ 树、不改为"每文件多列"。
- API 只增不减：既有签名保留；边查询通过新增带 target_id 的重载实现。
- 依赖不变：C++17；只用仓库已有依赖；不新增第三方库。
- 每个任务：先写失败测试 → 实现 → 测试通过 → 基准不回归（>5% 视为回归）→ 提交。没有测试的性能改动不接受。
- 基准口径：单线程与 8 线程；1 万/10 万/100 万行；记录 p50/p99、吞吐、峰值 RSS；机器与编译参数写入 benchmarks/RESULTS.md。

## Review Focus

- 单条记录 flush 后是否可读（1 行 SST）。
- Delete → flush → 重启后是否复活。
- 同一 src/type、不同 dst 的边在 MemTable 与 SST 两条路径是否都能精确命中。
- >8192 行的 edge SST 的 target 是否逐行正确。
- 并发 Put/Commit 与后台 flush 是否 UAF/丢节点。
- 压缩是否混合列、是否删除未合并的下层文件、是否撞文件号。
- 损坏/截断 SST 是否越界读或静默返回部分结果。
- 大 value（Blob）读写与崩溃后的可恢复性。
